## 1. 文档包目标

本项目包含两个代码库：

```text
dataest-pipeline
    负责 geometry + condition + budget 的 teacher 数据生成
    产出 target mesh、error indicator、stage fields 和 reference solution

amber
    负责学习 teacher mesh
    包含原始 AMBER、physics-weighted imitation 和 gated physics correction
```

黄迪同学完成的工作位于两个代码库之间：将 pipeline manifest 和物理产物转换为 AMBER 可使用的 `SourceData/AmberData`，使现有 weighted imitation 与 physics correction 能消费 pipeline 数据。

本次工作安排不再讨论“如何把两个仓库第一次连起来”，而是解决以下问题：

1. 合并代码是否真的可以在当前目录和声明环境中运行。
2. 哪些代码缺口会使正式实验无效或不可复现。
3. 如何在相同数据、相同预算和相同训练条件下比较原始 AMBER、物理加权和物理修正。
4. 如何区分“物理特征输入的收益”和“gated residual correction 的收益”。
5. 如何用真实 PDE error，而不只是 sizing imitation error，判断方法是否更好。
6. 如果主方案表现不佳，可以采用哪些有边界的备选思路。

## 6. 统一优先级

### P0：不完成就不能开始可信实验

- 修复旧绝对路径和错误诊断。
- 固定 Python 3.11 环境并通过相关测试。
- 新增未加权 pipeline baseline。
- 完成真实 PDE evaluator。
- 固定数据、split、filter 和指标定义。
- 保存 checkpoint、resolved config、逐样本 CSV 和版本 hash。
- 推送本地 adapter 与 pipeline 提交。

### P1：用于隔离方法贡献

- feature-only gate-zero 控制组。
- indicator correction 与 stage-field correction 对比。
- joint 与 PDE-specific 诊断。
- geometry-level 统计和不确定性。

### P2：只有主实验闭环后才考虑

- ABC 扩展。
- 额外 GNN baseline。
- 更多 physics field 融合方式。
- 多预算泛化。

## 7. 创造性内容使用规则

> **重要提醒：** `03` 至 `08` 中涉及模型修改、实验矩阵、指标主次、阈值和备选路线的内容，属于基于当前代码和数据审计提出的候选方案，不是已经被实验验证的结论。执行前应由研究者额外思考并确认：研究问题是否一致、变量是否公平、数据语义是否正确、算力是否允许、实现是否会引入新的混杂因素。不能因为文档给出建议就机械执行。

具体遵循：

1. 事实性结论以 `02` 为准。
2. 每项创造性提议先写出它要回答的问题，再决定是否实施。
3. 优先采用只改配置或评估器的最小方案。
4. 新模型修改必须有对应控制组，否则不进入正式实验。
5. 如果备选方案改变了研究问题，应另行记录，不与主方案结果直接混合。
6. 任何指标阈值都应在看 test 结果前固定。

## 8. 完成状态定义

项目代码与实验工作完成，应同时满足：

- 当前目录移动后仍可读取数据。
- 声明环境可从零建立，相关测试全部通过。
- 原始 AMBER、weighted、feature-only 和完整 correction 使用同一数据协议运行。
- 每个模型输出有效 mesh，预算偏差可比较。
- 每个 test sample 都有 sizing、PDE、预算、质量和 runtime 指标。
- 主方法至少有多个固定 seed 的结果。
- 所有聚合值可以追溯到逐样本记录、checkpoint、resolved config、commit 和 manifest hash。
- 对主方案不利的结果也被保留，而不是通过事后筛选隐藏。

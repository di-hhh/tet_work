# 对比实验设计与备选路线

## 文档信息

- **修改内容**：独立整理主对比、控制变量、公平协议、最小实验集和多种备选实验路线。
- **文档概述**：本文定义如何比较原始 AMBER、physics-weighted imitation 和 gated physics correction。设计重点是避免把“使用了 condition-dependent stage field”与“gated residual 架构有效”混为一谈。主比较既包含几何输入的原始 AMBER和 weighted AMBER，也包含看到相同 stage field 但不使用 residual correction 的 feature-only 控制组。文档还给出 uniform/initial mesh、teacher oracle、PDE-specific model 等参照，以及在算力不足、PDE evaluator 不稳定、ABC 缺失或完整方法不占优时可以切换的备选路线。

## 1. 创造性方案提醒

> **重要提醒（需要额外思考）：** 本文的实验矩阵是根据当前代码和条件信息流提出的候选设计。正式执行前应重新画出每个方法可见的输入、监督和 checkpoint 来源，确认不存在信息不对称。尤其需要判断：原始/weighted AMBER 在同 geometry 多 condition 下是否存在不可辨识目标；feature-only 是否确实让 expert path 看到 stage field；从 weighted checkpoint 初始化是否造成训练预算不公平。

## 2. 研究问题

建议将实验拆成四个可验证问题：

1. 在相同 condition-aware teacher 数据上，physics-weighted loss 是否优于原始 imitation loss？
2. 给模型输入 condition-dependent stage field 是否比 geometry-only 输入更好？
3. 在看到相同 stage field 时，gated residual correction 是否优于单一 expert path？
4. 改善是否体现在真实 PDE error，而不仅是 teacher sizing imitation error？

## 3. 主对比矩阵（你需要根据当前 @对030408的实现报告.md 真实实现，向我确认）

| ID | 方法 | Loss | 模型输入 | Final 路径 | 主要作用 |
|---|---|---|---|---|---|
| R0 | Initial/Uniform mesh | 无训练 | 几何 | 固定网格 | 非学习参照 |
| R1 | Teacher target | Oracle | 全部 teacher 信息 | target mesh | 可达到的 teacher 上界 |
| M0 | Pipeline 原始 AMBER | 未加权 | 几何/原始图特征 | expert head | 原始方法公平 baseline |
| M1 | AMBER + weighting | indicator linear weight | 与 M0 相同 | expert head | 隔离 loss-side weighting |
| M2 | Feature-only AMBER | indicator linear weight | M1 + stage field | expert head，gate=0 | 隔离 physics input |
| M3 | Indicator correction | indicator linear weight | M1 + indicator | expert + gated residual | correction 使用 indicator |
| M4 | 完整方法 | indicator linear weight | M1 + stage field | expert + gated residual | 当前主方案 |

推荐主结果至少包括 M0、M1、M2、M4。M3 可作为重要消融。

## 4. 关键公平控制

所有 M0-M4 固定：

- 相同 frozen manifest 和 quality filter。
- 相同 geometry split。
- 相同 backbone、latent dimension 和 normalizer。
- 相同 optimizer、learning-rate policy、batch policy。
- 相同训练停止/选择规则。
- 相同 inference steps 和 mesh generator 参数。
- 相同 desired/hard budget。
- 相同 evaluator 和 reference solution。
- 相同 seed 集合。

### 4.1 训练预算

M4 若从 M1 checkpoint 初始化，需要记录：

- M1 训练 epochs/steps。
- correction finetune epochs/steps。
- 总训练 wall time。

备选公平方式：

- 比较“相同总更新步数”。
- 同时报告“推荐两阶段流程”的最终性能和额外训练成本。

> **额外思考提醒：** 完全相同步数与相同训练策略不一定同时公平。应明确实验回答的是“方法在推荐流程下最好能达到什么”还是“相同计算成本下谁更高效”，必要时分成两个表。

**这点需要你向我确认**

### 4.2 Condition 信息不对称

M0/M1 不读取 stage field；M2/M4 读取 stage field。M4 对 M1 的提升不能单独归因于 correction。因此 M2 是必要控制。

如果同一 geometry 的 initial mesh 和基础图特征完全相同，而 target 随 condition 改变，则 M0/M1 无法在推理时区分 conditions。需要在结果中明确这一事实，并考虑 PDE-specific 参照。

**这点需要你想我确认**

## 5. 与原 AMBER 的比较方式

正确方式：在同一 pipeline 数据上关闭新增功能并重训 M0。

不正确方式：直接把原 AMBER 论文 Console/Mold 表格数字与当前 condition-aware 数据数字比较。

原因：teacher、condition、split、budget 和评价器均不同。

可选 bridge experiment：在原始 Console/Mold 协议上比较原 AMBER、weighted、correction，用于说明新增代码没有只对 pipeline 数据有效。但它是补充，不替代当前 pipeline 主比较。

## 6. 最小可行实验集

当算力有限时：

### 必须完整运行

- R0 Initial/Uniform。
- R1 Teacher oracle。
- M0 原始 AMBER。
- M1 weighted AMBER。
- M2 feature-only。
- M4 完整方法。

### Seed 规则

- M0、M1、M4：固定多个 seed，建议 0/1/2。
- M2：至少 seed 0；若其结果改变对 M4 的解释，则补齐多个 seed。
- M3：先用 seed 0 做机制判断。

### PDE 分组

所有结果分别报告：

- scalar elliptic。
- linear elasticity。
- joint aggregate，但 joint 不覆盖分项。

## 7. 增强实验集

主闭环完成后可考虑：

- PDE-specific M0/M1/M4。
- 原始 Console/Mold bridge。
- ABC external test。（ABC 数据集暂不使用）
- GraphMesh 或已有 GNN baseline。
- 不同 inference steps 的稳定性。
- runtime 与 teacher generation cost。

> **额外思考提醒：** 增强实验只有在能回答明确审稿问题时才加入。例如 PDE-specific 模型回答“joint learning 是否负迁移”，ABC external test 回答“是否跨 CAD 分布泛化”。不要仅为了增加表格行数运行实验。

## 8. 备选路线（这点你需向我确认，@对030408的实现报告.md 根据当前真实实现，以下备选方案有哪些需要选择？哪些无需选择，因为已有更强实现？）

### 8.1 备选 A：PDE evaluator 暂不稳定

先完成 sizing、budget、mesh validity 主矩阵，同时继续修 evaluator。

允许用于调试，不建议将其作为最终物理结论。若最终仍无 PDE error，结论只能收缩为 critical-region imitation 改善。

### 8.2 备选 B：ABC 不可用

冻结 Mold-69；强化：

- geometry-level 统计。
- PDE 分项。
- 多 condition 可视化。
- failure analysis。

不再让 ABC 数据工程阻塞主闭环。

### 8.3 备选 C：M4 不优于 M1

优先检查：

- physics feature 是否加载。
- gate 是否饱和/全零。
- correction 是否被过强正则压制。
- expert-only 与 final 的差异。

只允许少量有依据的参数修正。若仍无提升，将 M1 作为主方法，M4 作为负结果或机制分析。

### 8.4 备选 D：M2 与 M4 相当

说明主要收益来自 stage-field input，不是 gated correction。

可将主要方法解释收缩为 condition-aware feature injection + weighted imitation；不继续堆叠 gate 结构。

### 8.5 备选 E：Joint 模型表现差

训练 scalar-only 和 elasticity-only 模型作为诊断：

- 若 PDE-specific 显著更好，说明 joint model 存在负迁移或 condition 表示不足。
- 可选择分 PDE 报告模型，或考虑最小 PDE-type feature。

> **额外思考提醒：** 加入 PDE-type one-hot 或 condition encoder 会改变模型输入和研究贡献。只有 feature-only/PDE-specific 诊断明确支持后才考虑，且必须增加新的公平 baseline。

## 9. 结果解释模板

- M1 优于 M0：支持 physics-weighted loss。
- M2 优于 M1：支持 condition-dependent physics feature。
- M4 优于 M2：支持 gated residual correction 的净贡献。
- M4 仅优于 M1、不优于 M2：不能声称 gate 有独立贡献。
- sizing 指标改善但 PDE error 不改善：只能声称 teacher imitation 改善。
- PDE error改善但预算显著增加：不能视为公平提升。
- aggregate 改善但某 PDE 明显退化：需分项报告，不能只报平均。

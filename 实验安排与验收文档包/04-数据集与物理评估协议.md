- **修改内容**：独立定义当前 Mold 数据、可选 ABC 扩展、划分过滤、版本冻结和真实 PDE 评估协议。
- **文档概述**：本文用于在正式实验前固定数据和评估语义，防止不同方法使用不同样本、不同过滤、不同预算或不同参考解。文档首先记录当前 Mold-69 数据的事实状态，然后定义 geometry-level split、quality/status 过滤、单 budget 主协议、数据版本文件和泄漏检查。随后给出真实 PDE 评估的推荐方案，以及 ABC 不可用、少量可用和充分可用时的备选路线。数据扩展是否实施，应由其对主研究问题的增益、数据有效性和工程风险决定。

## 1. 使用提醒

> **重要提醒（需要额外思考）：** 数据集范围、过滤规则、reference solution 强度和 PDE 主指标都会直接改变研究结论。本文的主协议是基于当前产物提出的候选固定方案，正式采用前应额外检查 teacher solver 的物理语义、scalar cheap-reference 的精度、condition selector 在预测 mesh 上的可重建性，以及 69 个 geometry 是否足以支持目标结论。

## 2. 当前数据事实

数据源：`mold_local_3d`。

固定 desired budget：7000 elements。

原始成功样本：276；默认 quality filter 后：258。

| Split | Raw | Quality-pass |
|---|---:|---:|
| train | 192 | 182 |
| val | 40 | 34 |
| test | 44 | 42 |

PDE 分布：scalar elliptic 与 linear elasticity 各 138 个原始样本。

Geometry split：48/10/11，跨 split 无交集。

每个 geometry 通常有多个 condition，因此样本不是独立 geometry。

## 3. 主数据协议

### 3.1 样本保留

默认保留：

```text
status in {
  success_budget_closed,
  success_near_desired_budget
}

quality_verdict in {
  PASS_STRONG,
  PASS_WEAK
}
```

默认排除：

- `FAIL_GLOBAL_OVERREFINE`。
- indicator 或 target 缺失。
- 无 tetra target。
- indicator 与 tetra 数量不匹配。
- stage-field 实验中 stage field/probe points 无效。

### 3.2 Split

- 按 `geometry_id` 分组划分。
- 同一 geometry 的所有 conditions 放在同一 split。
- 所有方法使用同一个 frozen split。
- test geometry 不参与参数选择和过滤调整。

### 3.3 Budget

主实验使用单一 desired budget = 7000，避免模型未显式接收 budget 时混入多预算目标。

报告预测 mesh 实际 elements 和 budget deviation，不能仅假设配置相同就代表预算相同。

### 3.4 Joint 与 PDE-specific 数据视图

主数据可以保留 joint scalar+elasticity，但建议额外生成只读过滤视图：

- `pde_family=scalar_elliptic`。
- `pde_family=linear_elasticity`。

它们用于分析 joint training 的负迁移和条件不可辨识问题，不另行随机划分。

## 5. 真实 PDE 评估协议

### 5.1 为什么必须有 PDE 评估

`weighted_size_l2` 衡量“是否更像 teacher 的重要区域尺寸分配”，不能直接证明求解 PDE 更准确。物理方法的核心证据应是相近 mesh budget 下的 solution/energy/QoI error。

### 5.2 推荐评估流程

```text
模型输出 sizing field
 -> mesh generator 生成预测 tetra mesh
 -> 根据该样本 condition_spec 重建 PDE
 -> 在预测 mesh 上求解
 -> 投影到公共 probe points 或 reference mesh
 -> 与 reference_solution.npz 比较
```

### 5.3 Scalar elliptic

候选主指标：

- volume-weighted relative solution L2。
- relative H1 seminorm/energy error。
- condition-defined QoI relative error。

### 5.4 Linear elasticity

候选主指标：

- relative displacement L2。
- strain-energy/elasticity-energy relative error。
- mean displacement norm 等 QoI relative error。

### 5.5 公共比较域

推荐使用固定 probe points 或 reference mesh quadrature points。不同预测 mesh 不能直接按节点下标比较。

### 5.6 Reference 强度检查

必须检查：

- reference mesh 是否通常比预测 mesh更细或更可靠。
- `reference_solution.npz` 是否对应同一个 condition。
- scalar cheap-reference 是否足以作为 ground truth。
- elasticity 的 support/traction selector 在预测 mesh 上是否一致。

> **额外思考提醒：** 如果 reference solution 只是 target mesh 自身解，而不是更高精度解，那么“模型相对 reference 的 PDE error”同时混入离散误差和投影误差。可将 teacher target 视为 oracle 上界，但必须明确其精度边界；必要时只对 test 集生成更强 reference。

## 6. ABC 备选路线

### 6.1 方案 A：不加入 ABC（目前的选择）

使用 Mold-69 完成所有公平比较。

优点：工程风险最低，现有 teacher 产物完整。

限制：geometry 数量和来源单一，外部泛化证据弱。

### 6.2 方案 B：ABC 只做外部测试（目前不选）

在 ABC 上生成少量 quality-pass test geometries，不用于训练，评估 domain shift。

优点：数据成本低于完整训练集；能提供外部泛化证据。

限制：如果 Mold 与 ABC 几何分布差异过大，所有方法都可能失败。

### 6.3 方案 C：ABC train/val/test（目前不选）

生成足够 geometry 和 conditions，作为独立主数据或与 Mold 联合训练。

优点：更接近真实大规模 CAD 泛化。

限制：STEP 清洗、teacher 成功率、计算成本和数据冻结复杂度高。

### 6.4 选择建议

优先保证 Mold 主协议闭环。只有 ABC smoke 显示：

- STEP ingestion 稳定。
- quality-pass rate 可接受。
- teacher 物理场非退化。
- geometry 数量足以做不泄漏划分。

才升级到方案 B/C。

> **额外思考提醒：** ABC 路线不是“数据越多越好”。ABC geometry 是否具有可定义的物理边界条件、condition selector 是否合理，比文件数量更重要。若条件是人工随意映射，扩充 ABC 可能反而削弱物理主张。

## 7. 数据有效性检查

每次冻结前检查：

- manifest JSON schema。
- sample ID 唯一性。
- geometry split overlap。
- 路径可解析性。
- tetra cell 存在。
- target/indicator shape。
- stage field/probe shape。
- condition/reference 对应关系。
- status/quality 数量。
- element budget 分布。
- importance 是否全零、常数或极端饱和。

## 8. 禁止事项

- 看过 test 结果后改变过滤规则。
- 为不同方法使用不同 quality-pass 样本。
- 将同一 geometry 的 conditions 拆到不同 split。
- 把原 AMBER 论文不同数据集的数字直接与当前结果计算提升率。
- 只报告成功生成 mesh 的样本而不报告 failure rate。
- 不报告实际 element count 就比较 PDE error。
- 将 Mold 数据称为 ABC 数据。

# 最终确认的实验路线

## 1. 执行目标

本路线用于执行冻结协议 `formal-mold7000-v3`。它只规定如何完成正式训练、评估与统计，不改变任何模型架构、forward、loss、数据 split、方法身份、指标或统计规则。

执行时以 [正式实验计划](../amber/config/formal_experiment_plan.yaml) 为机器权威，以 [正式实验前的确认项冻结](正式实验前的确认项冻结.md) 为人工核对清单。若与 05–08 文档中的旧顺序、旧路径或候选方案冲突，一切以当前真实冻结为准。

部署不属于本会话路线；待正式 `train/val/test` 和分析全部结束后另行考虑。

## 2. 总体阶段

```text
阶段 A：train
  16 次预注册 fit 顺序执行，绝不访问 test
        ↓
Gate T：Codex 验收训练产物
        ↓
阶段 B：evaluate
  一次性运行全部 test 导出、诊断、静态参照和 PDE evaluator
        ↓
Gate E：Codex 验收评估产物
        ↓
阶段 C：analyze
  按冻结统计规则生成正式汇总、配对比较和诊断结果
        ↓
Gate A：Codex 分析结论与边界
```

三个阶段不得合并为无人验收的一条端到端命令。

## 3. 08 文档的采用与替代关系

[08-实验执行与风险控制](../实验安排与验收文档包/08-实验执行与风险控制.md) 中以下原则继续采用：

- 评估后核对样本数、失败行、预算、PDE family 和跨 seed 协议一致性。
- 保留风险表与完整结果出来后的止损判断框架。

以下旧安排不再执行：

- 不使用第 139–175 行的旧绝对路径和旧 `main.py` 命令。
- 不按第 118–125 行在每个 checkpoint 后立即 test。

- 不根据训练中或单 seed 结果临时增加 PDE-specific、warmup、regularization、fixed gate 等实验。
- R0/R1 在统一 evaluate 阶段构建，不提前接触冻结 test。

## 4. 阶段 A：正式训练

### 4.1 训练顺序

运行器按照计划文件中的顺序串行执行，不并行启动 16 个训练：

| 顺序 | Analysis ID | Seed | 依赖 |
|---:|---|---:|---|
| 1 | M0 | 0 | 无 |
| 2 | M0 | 1 | 无 |
| 3 | M0 | 2 | 无 |
| 4 | M1 | 0 | 无 |
| 5 | M1 | 1 | 无 |
| 6 | M1 | 2 | 无 |
| 7 | M1-FT | 0 | M1 seed 0 `last.ckpt` |
| 8 | M1-FT | 1 | M1 seed 1 `last.ckpt` |
| 9 | M1-FT | 2 | M1 seed 2 `last.ckpt` |
| 10 | M2 | 0 | M1 seed 0 `last.ckpt` |
| 11 | M2 | 1 | M1 seed 1 `last.ckpt` |
| 12 | M2 | 2 | M1 seed 2 `last.ckpt` |
| 13 | M4 | 0 | M1 seed 0 `last.ckpt` |
| 14 | M4 | 1 | M1 seed 1 `last.ckpt` |
| 15 | M4 | 2 | M1 seed 2 `last.ckpt` |
| 16 | M3 oracle | 0 | M1 seed 0 `last.ckpt` |

每个 fit 为 101 epochs，推理步数固定为 3。`train` 只使用 train/val，不执行 test。

### 4.2 PowerShell 数量

Train 阶段建议新开 **2 个独立 PowerShell**，不需要为 16 个 run 各开窗口：

1. **PowerShell A：唯一训练窗口。** 启动正式 runner 后保持打开，不在此窗口输入其他命令。
2. **PowerShell B：只读监控窗口。** 用于查看 protocol status、GPU 状态和训练日志；可随时关闭重开。

只开 PowerShell A 也可以；PowerShell B 是为了监控方便。不得同时启动第二个 `train` 进程。

从 Windows 单独启动的 PowerShell 不依赖 Codex 进程。训练开始后可以关闭 Codex，但不能关闭 PowerShell A，也不能让系统睡眠、休眠或自动重启。

## 5. Train 中断与恢复规则

正式 runner 不自动删除任何 run：

- 已完整结束的 run 会保留；重新运行 `train` 时自动显示 `SKIP complete fit`。
- 正在运行或中断的 run 目录会保留已经写出的配置、元数据、日志、metrics 和 checkpoints。
- 若非空 run 没有完整完成标记，重新运行 `train` 会以 `Refusing to overwrite incomplete formal run` 停止。
- 这是一项防误覆盖设计，不是需要用户清理目录的提示。

发生以下任一情况时立即停止人工操作并保留现场：

- Python 返回非零 exit code。
- PowerShell 出现 traceback、CUDA OOM、NaN/Inf、DLL/import、磁盘或数据校验错误。
- 机器断电、重启、睡眠或进程意外消失。
- 某个 run 长时间无更新且 GPU 无活动。
- `status`、实际目录和控制台信息不一致。

然后向 Codex 提供：

1. PowerShell 最后约 100–200 行输出。
2. `python run_formal_experiments.py status` 的完整输出。
3. 发生异常的大致北京时间。
4. 是否发生过重启、睡眠、磁盘空间不足或手动操作。

在 Codex 验收前，不自行删除目录，不自行使用 checkpoint 恢复，不加 `--overwrite`，不重新开始该 run。

## 6. Gate T：Train 完成后的人工验收

当 PowerShell A 正常返回 exit code 0 后：

```powershell
python run_formal_experiments.py status
```

将完整输出交给 Codex。此时不要自行执行 `evaluate`。

Codex 至少核对：

- 16/16 run 均为 `fit_complete=true`。
- 每个 run 都存在精确的 `training_summary.json` 和 `checkpoints/last.ckpt`。
- 每个 run 状态为 `complete`，完成 101 epochs，update 数合理。
- 没有 NaN/Inf、异常退出或静默缺失。
- M1-FT/M2/M4/M3 加载了同 seed M1 checkpoint。
- M1-FT 是 weights-only 初始化且 optimizer/scheduler 为全新状态。
- 两个代码 commit、数据指纹、method/analysis ID、seed 和命令记录正确。
- Fit 阶段没有 test 产物。
- 训练耗时、峰值 GPU 显存和 validation 指标可读。

Gate T 只判断训练是否合法、完整和健康，不根据 validation 宣布正式科学结论。

不要添加 `--overwrite`。

Evaluate 阶段统一完成：

- M4 三个 seed 的同 checkpoint `expert_only` 输出。
- M2/M4 三个 seed 的同几何 condition shuffle。
- R0-Initial 与 R1-Teacher 静态 reference manifests。
- 主预测、M4 expert-only、shuffle 和两个 reference 的离线 PDE 评估。

Mesh/PDE 失败允许存在，但必须保留对应行。失败不是自动删样本或自动重跑的理由。

## 8. Gate E：Evaluate 完成后的人工验收

Evaluate 命令结束后，不要立即执行 `analyze`。先运行：

```powershell
python run_formal_experiments.py status
```

把状态和控制台输出交给 Codex。Codex 至少核对：

- 所有正式 checkpoint 都有完整 evaluation marker。
- 42 个冻结 test 样本身份和 PDE family 数量正确。
- M4 final/expert-only 确实来自同一 checkpoint hash。
- M2/M4 shuffle 规则和样本身份正确。
- 每个 PDE job 的 CSV/aggregate 均存在。
- 失败行没有丢失，joint-success 聚合正确。
- 数值指标只聚合 joint-success 行。
- element/vertex、预算、质量、QoI、计时字段非空且语义正确。
- 数据指纹、代码 commit 和 checkpoint hash 一致。

Gate E 只确认评估结果完整可信；正式比较由下一阶段统一完成。

## 9. 阶段 C：正式 Analyze

只有 Codex 明确确认 Gate E 通过后，才执行：

```powershell
& 'D:\anaconda3\shell\condabin\conda-hook.ps1'
conda activate AMBER_neurips
Set-Location -LiteralPath 'D:\SITP\tet_work\amber'

python -u run_formal_experiments.py analyze
```

分析必须使用冻结规则：

- geometry 是独立单位。
- geometry 内按 PDE 汇总 conditions。
- 多 seed 报告均值 ± sample std。
- 配对 geometry bootstrap 10,000 次、固定 seed 20260821、95% CI。
- 配对 Wilcoxon 与 Holm 校正。
- 主对比固定为 M1−M0、M1-FT−M1、M2−M1-FT、M4−M2。
- 补充对比为 M4 final−expert-only，以及 correct−shuffle。

分析结束后由 Codex：

1. 验收统计输入与输出。
2. 区分 sizing、PDE、预算、失败率和机制诊断结论。
3. 判断哪些预注册结论得到支持、未得到支持或证据不足。
4. 明确 M3 oracle、R0 非预算匹配、R1 非严格上界等解释边界。
5. 再决定是否需要任何后续诊断；不把候选诊断伪装成预注册主实验。

## 10. 方法①与方法②的最终选择

本轮选择方法①的受控版本：

```text
一个 formal_experiment_plan.yaml
+ 一条 train 命令顺序跑完 16 次 fit
+ Train 后人工验收
+ 一条 evaluate 命令
+ Evaluate 后人工验收
+ 一条 analyze 命令
```

不选择逐方法手抄底层命令的方法②，原因是：

- 当前 runner 没有正式的 `--method/--seed` 选择参数。
- 手抄 16 条 Hydra 命令更容易产生路径、seed、身份或 checkpoint 依赖错误。
- Pilot 已经覆盖六种方法的执行链，无需通过正式 test 逐个试错。
- 即使逐个训练，也不能在全部 fit 完成前访问 test 或给出正式结论。

如长时间训练中发生异常，则临时转入“保留现场 → Codex 验收 → 制定单次恢复方案”，但这不是预先采用方法②。

### 2.1 双锚点路径协议与旧数据兼容

主要实现位置：

- `dataest-pipeline/src/condition_aware_dataset_generation/serialization/path_protocol.py`
- `dataest-pipeline/src/condition_aware_dataset_generation/pipeline.py`
- `dataest-pipeline/src/condition_aware_dataset_generation/cli.py`
- `amber/src/tasks/pipeline_dataset_audit.py`
- `amber/src/tasks/pipeline_condition_aware_dataset_preparator.py`

最终协议：

1. pipeline output 内的新产物以 `pipeline_output_root` 为锚点保存相对路径。
2. output 外的几何源以独立 `geometry_source_root` 为锚点保存相对路径。（但是几何源默认在 tet_work/ 根内部；mold 几何源在 dataest-pipeline/data/mold/ 中）
3. 配置中的相对路径锚定各自仓库，不依赖调用命令时的当前目录。
4. 路径字段使用白名单，不对普通字符串做猜测式替换。
5. 现有 pipeline 配置检查 output/source 均位于 `tet_work/` 内；整个根目录复制后两个锚点仍随根目录移动。
6. `build_dataset_manifest` 只重新序列化 JSON/JSONL 路径字段，不重新求解 PDE、不重建 mesh，也不改写 `.npy/.npz/.vtk` 数值产物。这就是“不重新计算产物”的含义。
7. 相对路径写出逻辑属于 pipeline 通用协议，以后运行其他合规 YAML 也会生成相对路径，不只适用于 `default_fix_budget.yaml`。

旧绝对路径解析顺序严格保持已确认协议：

1. 相对路径：按相应锚点解析；
2. 绝对路径且仍存在：直接使用；
3. 绝对路径不存在且匹配显式 `old_root`：替换为 `new_root`；
4. 仍不存在：记录结构错误并使整个审计/数据加载失败。

Legacy relocation 默认关闭，必须显式提供 `enabled/old_root/new_root`。冻结指纹使用与机器位置无关的 portable identity；即使旧根在复制测试时仍存在，显示顺序和文件排序也不会把旧机器绝对路径写进指纹。相关回归覆盖“旧根仍存在”和“旧根已消失”两种情况。

Pipeline `runtime/*_input.json`、`*_output.json` 和 `status.json` 是单次 worker IPC/诊断文件，可能含本机绝对路径；它们不是可恢复数据集的 canonical manifest。恢复、审计和 AMBER 消费使用重新序列化的 geometry/prescreen/teacher/sample/split/preprocess manifest。复制根目录重新跑 pipeline 时会重新生成 runtime IPC，不能把它与正式数据协议混为一类。

### 2.2 数据审计与自动 SHA-256 指纹

主要实现位置：

- `amber/audit_pipeline_dataset.py`
- `amber/src/tasks/pipeline_dataset_audit.py`

审计和训练 adapter 共用解析、过滤和结构验证逻辑。最终实现包括：

- status、quality、显式 metadata filter 分项计数；
- path missing、mesh read、no tetra、target/indicator/stage/reference shape、重复 sample ID、split overlap、required split empty 等结构错误分类；

- JSON/CSV 输出 raw/retained split、geometry overlap、PDE/status/quality 分布、budget、importance 退化诊断和 consumed paths；
- `--freeze-fingerprint` 与 `--verify-fingerprint`，变更时报告 changed/missing 文件。

“全部样本 SHA-256”没有形成手工维护负担：程序只对 retained 数据实际消费的**唯一文件集合**分块哈希，同一文件只哈希一次。以后 pipeline 产生新数据集时，审计器从新 manifest 动态枚举文件并生成新的指纹，不需要人工扩展文件清单。本次正式指纹覆盖 1,586 个唯一文件，所有 identity 均为 `geometry_source/...` 或 `pipeline_output/...` 形式，没有绝对路径。

### 2.5 强 reference 与离线 PDE evaluator protocol v2

主要实现位置：

- `dataest-pipeline/evaluate_pipeline_pde.py`
- `dataest-pipeline/src/condition_aware_dataset_generation/evaluation/pde_evaluator.py`
- `dataest-pipeline/src/condition_aware_dataset_generation/teacher_generation/pde_solvers.py`

实现和修复结果：

1. 只为 retained test 样本发布强 reference。
2. reference mesh 是 target tetra mesh 的一次 uniform refinement，element 强度比固定为 8。
3. 22 个 elasticity 样本重新在 uniform-refined mesh 求解；20 个 scalar 样本仅在现有解严格通过 target 对应关系和 8×审计时复用。
4. reference 单独写入 `evaluation_references/v2/`，不覆盖 teacher reference。
5. 42 个样本全部成功后才原子发布 `manifests/evaluation_reference_manifest.jsonl`；失败报告在成功后不存在。
6. 每项绑定 condition ID/hash、PDE family、target mesh hash、refinement level、target/reference elements、source kind 和 solver metadata。
7. 修复了用 point probe 读取自身边界节点导致的 `Point is outside of the mesh`；P1 nodal solution 改为直接提取 nodal DOF。
8. evaluator 复用 `solve_condition`、condition/preprocess record、boundary selector 和点值计算，不在 AMBER validation step 内运行昂贵 FE。
9. 预测解在固定 reference-domain 点上比较，不按不同 mesh 的节点下标比较。
10. reference 点略超出预测粗网格边界时，protocol v2 使用最近 boundary triangle 的 P1 trace 投影，并输出 extrapolation 数量、比例、最大距离和 bbox 比例；超出点比例大于 10% 或最大距离大于 bbox 对角线 3% 时硬失败。
11. scalar 输出 volume-weighted relative solution L2 和 boundary-average QoI relative error；elasticity 输出 volume-weighted relative displacement L2 和 mean-displacement-norm QoI relative error。
12. 每样本还输出 solver status、predicted/reference elements、budget ratio/deviation、reference strength、runtime、method/seed/checkpoint/fingerprint；失败数值列为空且进入失败率，不造伪数值。

本次实现的是用户确认的“可靠 QoI 前者”。H1/energy norm 需要另行验证梯度投影、体积积分和边界条件，未冒充完成，也不影响当前协议的 L2 + QoI 主指标。

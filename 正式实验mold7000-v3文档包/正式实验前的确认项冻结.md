## 3. 不可改变的硬边界

本轮正式实验确认：

- 不修改模型架构。
- 不修改模型 forward 公式。
- 不修改 loss 公式。
- 正式产物按 M0–M4 组织；M1-FT 是额外训练预算的辅助公平控制，不是新模型架构。
- M3 明确标记为 `oracle_only`，不得作为可部署主方法或与非 oracle 方法混同宣传。
- M2/M4 的 stage field 必须从 `probe_points` 直接 IDW 投影到每一步的当前 learner mesh。
- M2/M4 的正式 stage-field 路径不得读取 expert mesh。
- 每个方法使用 `inference_steps=3`。
- 每次正式 fit 使用 `101 epochs`。
- 训练期间不运行 test；全部 16 次预注册 fit 完成并验收前，不得访问冻结 test 结果。
- WandB 在正式协议中关闭，结果以本地产物为准。
- 不报告 Energy/H1 指标。
- 不把冻结强 reference 称为 ground truth；统一称为“相对冻结强 reference 的差异”。

## 8. 指标冻结

### 8.1 PDE 指标

- 一级指标：`solution_l2_relative`。
- 语义：相对冻结强 reference 的差异，不是相对 ground truth 的绝对真误差。
- 二级指标：`qoi_absolute_error`、`qoi_relative_error`。
- Mesh generation 与 PDE solver 均成功时才记为 joint success。
- 所有失败样本必须保留行，并记录 mesh、solver、joint 三类成功状态以及失败类别和原因。
- 数值均值只在 joint-success 行上聚合，同时显式报告失败数和失败率。

### 8.2 Sizing 与关键区域指标

- 主 sizing 指标：`projected_l2_error_symmetric`。
- 关键区域指标：`physics_weighted_projected_l2_error`、`weighted_size_mse`、`topk_high_importance_mse`。
- Top-k 固定为重要度最高 20%，重要度 bucket 数固定为 5。
- 实现中的 weighted/top-k/bucket 指标真实计算为 MSE。
- 为兼容旧产物保留历史 `_size_l2` 字段，同时提供语义正确的 `_size_mse` 别名；分析时不得把旧字段误解为开平方后的 L2/RMSE。

### 8.3 网格、预算、质量与效率

- 从实际 VTK/mesh 导出读取 vertex 数和 element 数。
- 记录 element budget ratio、绝对偏差、相对偏差、close/valid 状态。
- 目标单元数为 7,000；close 相对容差为 18%。
- Valid ratio 为 `[0.8, 1.5714285714285714]`，对应约 `[5,600, 11,000]` 个单元。
- 记录质量最小值、q05、中位数，以及退化、翻转、非法单元的数量和比例。
- 训练和推理计时执行 GPU synchronization，并区分 warmup 与 steady-state。
- PDE solver 的纯求解时间与后处理时间分开记录。
- Teacher generation 时间只能标记为整样本生成时间，不能伪称为隔离的 stage-field 生成耗时。
- Energy/H1 未实现且不进入正式结果。

## 9. 统计冻结

- 独立统计单位：`geometry_id`，不是单条 condition 样本。
- 同一 geometry 内先按 PDE 对 conditions 求均值。
- 多 seed 先形成每个 seed 的 geometry 汇总，再报告跨 seed 均值 ± sample standard deviation。
- 配对 geometry bootstrap：10,000 次；固定 seed 20260821；置信水平 95%。
- 配对 Wilcoxon：启用；多重比较校正：Holm。

预注册对比：

| 对比 | 只用于支持的结论 |
|---|---|
| M1 − M0 | physics-weighted loss 的贡献 |
| M1-FT − M1 | 额外训练预算的影响 |
| M2 − M1-FT | stage feature 的独立贡献 |
| M4 − M2 | 完整 gated residual stack 的增益 |
| M4 final − M4 expert-only | 同一 checkpoint 下 gate/final 组合的作用 |
| M2/M4 correct − shuffled | 条件响应性与 stage field 是否被真实使用 |

不得用单 seed、单指标或删除失败样本后的结果触发重大路线结论。

## 10. Train/Test 隔离与阶段门禁

正式流程固定为：

```text
train（16 次 fit，禁止 test）
→ 人工验收全部训练产物
→ evaluate（统一接触冻结 test）
→ 人工验收评估产物
→ analyze（冻结统计规则）
```

- `train` 不调用 test。
- `evaluate` 在任一预注册 fit 缺少完整 `training_summary.json` 或 `checkpoints/last.ckpt` 时必须拒绝启动。
- 首个或中间某个方法完成后，只允许检查训练健康度、validation、checkpoint 和元数据；不得生成正式 test 结论。
- 训练完成后的第一次 test 访问必须通过统一 `evaluate` 入口。
- `analyze` 必须等待全部 PDE 评估文件存在。

## 11. Run 目录与中断保全

正式根目录固定为 `amber/output/formal_experiments/formal-mold7000-v3`。每个 `analysis_id/seed` 使用独立目录。当前代码没有自动清理 run 目录的逻辑：

- 完整 run 同时存在 `training_summary.json`、`checkpoints/last.ckpt` 且 summary 状态为 `complete`；再次运行 `train` 时会自动跳过。
- 中断或失败的非空 run 会保留现场；再次运行 `train` 时会拒绝覆盖并停止。
- 训练产生的配置、元数据、日志、metrics 和 checkpoints 不会由正式 runner 自动删除。
- `evaluate` 默认跳过已有完成标记的评估；正式流程不使用 `--overwrite`。
- 用户不得自行删除、移动、重命名或覆盖任何 formal run；发生异常后应保留 PowerShell 输出和目录原状，交由 Codex 验收。

只有用户或其他外部程序主动清理、磁盘故障，或明确运行覆盖性操作，才会破坏这些产物；正式流程本身不会清理它们。
